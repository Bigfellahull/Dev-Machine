# Global Instructions

## Code Style

- Keep inline comments minimal and reserved for genuinely complex code. Only explain the **why**, never the **what** — the code itself should be readable enough. If the logic is straightforward, no comment is needed.
- Add language specific comments to all public methods and types.

## Pasteable Output

When asked for pasteable output (Trello cards, emails, chat messages, tickets, docs, etc.), use plain text only (no markdown). Do not wrap lines mid-sentence — each sentence or bullet point should be a single unwrapped line so it pastes cleanly into the destination without spurious line breaks.
